# Phase 2: 상시 PC의 YDown 추출 서버 검토

Phase 1은 https://ydown.yebom.org 에서 최신 로컬 앱을 배포하는 것이다.
이 문서는 상시 PC를 사용하는 서버의 개발 범위이며 아직 서버 공개를 구현한 것은 아니다.

## 현재 확인한 조건 (2026-10-12)

- 사용자는 현재 개발 PC가 성경음원 생성·받아쓰기용 상시 PC이며, 이 PC에서 로컬 YDown이 정상 동작한다고 확인했다.
- Windows 11 Home, Intel Core i7-10700KF (8코어/16스레드), 약 16GB RAM, NVIDIA RTX 2060 SUPER.
- 조사 시점 사용 가능한 RAM은 약 4.5GB, CPU 사용률 표본은 36%, C: 여유 공간은 약 342GB였다. 시점 측정이며 기존 작업의 최고 부하를 측정한 결과가 아니다.
- 현재 YDown은 GPU나 음성 인식/생성 모델을 사용하지 않는다. 주요 부하는 yt-dlp의 네트워크 다운로드, FFmpeg의 CPU 오디오 변환, 임시 디스크 저장, 사용자에게 파일을 전송하는 업로드이다.
- 320kbps MP3 결과의 크기는 1시간당 약 144MB(십진수, 헤더 제외)이다. 입력 파일과 임시 파일을 합친 디스크 사용량은 더 크며 M4A/Opus는 달라질 수 있다.

## 권장 구성

브라우저 → 별도 서버 주소의 HTTPS/접근 제한 → 이 PC의 YDown 전용 포트/프로세스 → YouTube.

다운로드 안내 주소는 Phase 1로 유지하고, 추출 서버에는 별도 주소를 사용한다.
YouTube 요청은 이 PC의 인터넷 연결로 나가야 한다. 입구용 터널/역방향 프록시를
설정하는 것은 yt-dlp의 YouTube 출력 프록시를 설정하는 것과 다르다.
실제 외부 접속 경로에서도 추출·변환·파일 저장을 끝까지 검증해야 한다.
현재 로컬 성공이 미래 또는 모든 영상의 성공을 보장하지는 않는다.

## 개발 범위

1. 소수 사용자의 시범 서버: 전용 데이터 폴더와 충돌하지 않는 포트, 제한된 사용자 접근,
   Windows 재부팅 시 자동 실행과 실패 시 재시작, 동시 추출 1개, FFmpeg 자원 제한.
2. 기존 작업 보호: 제한된 작업 대기열과 사용자별 요청 제한, 취소/진행 상태,
   파일 보관/저장 공간 한도, 로그와 상태 점검. 현재 서버는 대기열 없이 바쁠 때 새 요청을 거절한다.
3. 운영 검증: 성경음원 생성·받아쓰기의 대표 작업과 동시에 실행해 CPU/RAM/처리 시간,
   영상 길이별 변환 시간, 업로드 속도와 다운로드 완료, 재부팅 복구를 측정한다.

첫 공개는 소수 사용자·동시 1개 작업으로 제한하는 것이 적절하다. GPU 작업 자체를
추가하지 않더라도 기존 작업의 CPU/RAM/디스크/네트워크와 경합할 수 있다.
본격 다중 사용자 서비스는 계정별 파일 접근, 영속 작업 관리, 사용량 제한이 추가로 필요하다.

개발량은 기본 추출기를 새로 만드는 것보다 작지만, 실제 운영 안정화를 위한 중간 규모 작업이다.
환경 설정이 원활하다는 가정에서 시범 연결은 대략 1~2 작업일, 제한된 사용자용 운영 기능과
동시 부하 검증은 추가 3~5 작업일을 예산으로 잡을 수 있다. 접근 경로·사용자 수·기존 작업과의
연계 범위가 정해지기 전의 계획 추정이며 검증 완료나 일정 확약은 아니다.
